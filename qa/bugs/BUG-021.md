# BUG-021: Asking again adds duplicate and competing suggestions: stacked pins, inflated counts, up to three pending cards for the same line
Severity: S3
Priority: P1
Status: Open
Flow / TC-ID: Tailoring / suggestion list / TC-AIQ-004, TC-AIQ-007, TC-AIQ-008, TC-AIQ-034
Devices: laptop-chrome (same code on phones: sheet shows 'Review 31')
URL: /app/editor workspace
Frequency: Always
Build / env: local isolated copy of the CURRENT working tree (branch resume-llm, uncommitted on c53d3dc), vite http://127.0.0.1:5612 + real API server http://127.0.0.1:5611 (only an LLM key in env), 2026-11-25 IST

## Steps to reproduce
1. Tailor a job (8 suggestions, incl. 'drop vendor bullet' E0B7 and 'remove catalog bullet' E2B4, 3 pending cards for Skills over the session).
2. Ask 'can you make it fit one page?' then 'remove the weakest bullets' (without applying).
3. Or: answer a question card about the summary: a second Summary card is added.

## Expected
A request that repeats a pending suggestion does not create a second card; the reply says so.

## Actual
'make it fit one page' adds 8 cards, 2 of them identical to pending A0 cards (E0B7, E2B4). 'remove the weakest bullets' adds 8 more, ALL 8 duplicates of the previous 8, while the reply says 'They're the same ones I suggested for the one-page cut, so if you already applied those, there's nothing new here. ... I've added 8 suggestions to the list'. Header becomes '0 of 29 suggestions applied', tabs 'All 29 / To review 29'; at the end 'All 31'. Pins pile up on one line (1 and 13 on the Summary, 14 and 5, 15 and 23). Answering the mentoring question adds a second Summary card (#2) beside #1: two competing rewrites of one line. Skills: 3 pending set_skills cards (24, 17 and 15 items) at once.

## Evidence
- Screenshots: qa/runs/2026-11-25_1425/screens/laptop-chrome/B2-weakest-bullets.png (0 of 29, stacked pins), R2-answer-question.png (two Summary cards), qa/runs/2026-11-25_1425/screens/iphone-14/S3-sheet-first-card.png (pins 1 and 13 overlap)
- Data: qa/runs/2026-11-25_1425/scenarios/turns.json B1, B2 (repeats); R2 in turns-r3.json

## Probable cause
src/ResumeLLM.jsx act.ask (src/ResumeLLM.jsx:969) and addCards (src/ResumeLLM.jsx:819) append every returned card with a new pin; no check against pending/applied/dismissed suggestions on the same target or with the same edit. server/tailorChat.js chatTurn also gets no list of existing suggestions.

## Suggested fix
In addCards drop (or merge) a card whose target+op+normalised text equals an existing non-dismissed card, and mark an older pending card for the same line as 'replaced' when a newer one arrives; send the pending/applied targets to chatTurn so the model can say 'already suggested (#5)'.

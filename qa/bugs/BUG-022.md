# BUG-022: Apply all applies several suggestions for the same line one after another: all show Applied, only the last survives, the count overstates what changed
Severity: S3
Priority: P1
Status: Open
Flow / TC-ID: Tailoring / Apply all / TC-AIQ-005
Devices: laptop-chrome, laptop-safari, laptop-firefox (button is laptop only)
URL: /app/editor workspace
Frequency: Always (follows BUG-021)
Build / env: local isolated copy of the CURRENT working tree (branch resume-llm, uncommitted on c53d3dc), vite http://127.0.0.1:5612 + real API server http://127.0.0.1:5611 (only an LLM key in env), 2026-11-25 IST

## Steps to reproduce
1. Have 3 pending Skills suggestions (reorder 24, trim to 17, trim to 15) as in TC-AIQ-004.
2. Click 'Apply all ready'.

## Expected
Conflicting suggestions for one line are not applied together (or the earlier ones are marked replaced); the count matches distinct changes.

## Actual
Header '8 of 11 suggestions applied', Applied tab 8, all three Skills cards show a tick, final resume skills = 15 items (the last card only). Undo on an earlier Skills card restores the skills value captured at its own apply time, which is the previous suggestion's output, not the original.

## Evidence
- Screenshot: qa/runs/2026-11-25_1425/screens/laptop-chrome/A4-applyall.png
- Data: qa/runs/2026-11-25_1425/scenarios/A4-applyall.snap.json (suggestions 8, 10, 11 all 'applied', resume.skills length 15)

## Probable cause
src/ResumeLLM.jsx act.applyAll (src/ResumeLLM.jsx:870-891) loops over every pending suggestion and applies each to the running resume without grouping by target.

## Suggested fix
Group by line; apply only the newest per line and mark the others 'replaced'; or hold conflicting ones back like the ownership-warning cards.

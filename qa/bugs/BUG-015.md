# BUG-015: 'Start a new chat' cannot escape a crash caused by a chat that is not the active one (crash loop with no in-app way out)
Severity: S4
Priority: P2
Status: Open
Flow / TC-ID: Error boundary / state, TC-REG-046, TC-REG-048
Devices: all 7 projects (same code)
URL: /app/editor
Frequency: Always
Build / env: local isolated copy of the CURRENT working tree (branch resume-llm, uncommitted fixes on c53d3dc), vite dev on http://127.0.0.1:5473, fake Supabase, /api mocked, fake Razorpay, no live keys, 2026-11-25 IST

## Steps to reproduce
1. localStorage riq_resume_llm_v1 holds chats c1 (resume.experience is a string), c2 (same), c9 (healthy), activeId = c1. (Or: activeId null/unknown with one broken chat.)
2. Open /app/editor. Crash screen appears. Tap 'Start a new chat'. c1 is removed, activeId set to null.
3. Page reloads and crashes again (c2 is still broken even though no chat is active).
4. Tap 'Start a new chat' again.

## Expected
The crash screen can always be cleared by its own button.
## Actual
With activeId null (or stale), removeActiveChat filters nothing, so the store is unchanged and the page crashes on every load. A healthy chat plus an active ID renders fine (no crash), so something renders data from all stored chats only when no chat is active (start screen / recents list). Only clearing site data escapes. Crash message: TypeError: (r.experience || []).forEach is not a function.
## Evidence
- Tests: qa/tests/regress2.spec.ts TC-REG-046, TC-REG-048 (annotation: crashAgain=true ids=["c2","c9"]); screenshots under qa/runs/regress-pass2/
## Probable cause
src/App.jsx removeActiveChat (activeId null after the first reset) and an unguarded render of every chat's resume when activeId is not set (src/ResumeLLM.jsx, near line 349 / recents).
## Suggested fix
In removeActiveChat, when no active chat matches, fall back to removing the whole key (or every chat that fails a shape check); and make the start screen / recents list tolerate a malformed resume.

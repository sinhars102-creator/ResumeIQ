# BUG-011: ErrorBoundary 'Start a new chat' deletes the entire saved chat store (every chat), with no confirmation
Severity: S3
Priority: P1
Status: Partially-Fixed
Flow / TC-ID: Error boundary / TC-REG-015
Devices: all 7 projects (same code; TC-REG-015 fails on all 4 projects that run it, laptop x3 and phones)
URL: /app/editor
Frequency: Always
Build / env: local scratch copy of the working tree on top of c53d3dc, http://127.0.0.1:5273 (fake Supabase, API mocked, no live keys), 2026-11-24 IST

## Steps to reproduce
1. Save two chats in localStorage key riq_resume_llm_v1; make the active one crash on render (resume.experience is a string).
2. The 'Something went wrong on this page' screen appears. It says 'Your resume is safe'.
3. Tap 'Start a new chat'.

## Expected
Only the broken chat is dropped (or the user is asked first); the other chats survive.
## Actual
App.jsx passes onReset={() => localStorage.removeItem("riq_resume_llm_v1")}, which removes the whole store: every chat, resume and suggestion. A spy on Storage.removeItem recorded riq_resume_llm_v1. For a signed-in user the server copy (/api/rllm/state) may merge the chats back on reload, so a bad chat from the server could also bring the crash back in a loop (not tested end to end).
## Evidence
- Test: qa/tests/regress.spec.ts TC-REG-015 (annotation removed-keys); run qa/runs/regress-final
## Probable cause
src/App.jsx onReset removes the whole key.
## Suggested fix
Remove only the active chat (or move it to a backup key) and confirm first; change the copy so it does not promise 'Your resume is safe' for the destructive button.

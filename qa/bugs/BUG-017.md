## Steps to reproduce
1. Open /app/editor with a resume whose summary has `high‑scale`, `supply‑side` (U+2011), `data‐driven` (U+2010), `take−rate` (U+2212) and a quoted “merchant growth” (U+201C/U+201D).

3. Open suggestion 1 (Summary). Deterministic version: `node qa/llm/esc001.mjs`, `node qa/llm/esc001b.mjs`.

## Expected
A line that only gets a lookalike-character change (or the model's ASCII version of the same word) shows no strike and no chip. A suggestion whose only change is a dash variant plus one dropped article is not offered.

## Actual
Current block: ~~high-scale~~ ~~supply-side~~ ~~"merchant growth"~~ struck; Suggested block: the same words re-added in green; chip row 'Adds high-scale  supply-side  compliance  data-driven' (all already on the resume). After Apply all, high-scale / supply-side / data-driven / merchant / growth / compliance are green-highlighted on the resume though they read the same. Reverse case (ASCII on the resume, U+2011 from the model): chip 'Adds high scale' (esc001b.mjs).
Code points: U+2011 (high‑scale, supply‑side, B2B‑B2C, ananya‑iyer), U+2010 (data‐driven, pricing‐experiment), U+2212 (take−rate), U+201C/U+201D (“merchant growth”), U+2019 (I’m).
Hypothesis check: a PURE dash/quote difference IS dropped by cleanEdit (plain() strips every non a-z0-9 char; esc001.mjs: cleanEditResult dropped for U+2010, U+2011, U+2013, U+2212). The escape is: (a) the model returns ASCII hyphens/straight quotes for lines that hold special ones, plus any small real change (a dropped article, 'compliance.' -> 'compliance', 'Took' -> 'took'), so the edit is kept; (b) wordDiff and the chip logic then compare exact strings.

## Probable cause
- src/wordDiff.js:7-8 splits on whitespace and compares with === (no normalisation) and src/ResumeWorkspace.jsx Diff() renders those runs as del/ins.
- src/ResumeLLM.jsx:1000-1004 wsKeywords: tokenizeForMatch (src/matchScore.js:29-33) maps every char outside [a-z0-9+#./\s-] to a space, so U+2011 splits `high‑scale` into 'high','scale' while ASCII `high-scale` stays one token; `had` is built from the card's own line only (s.before), not the whole resume.
- server/tailorChat.js:247 plain() accepts near no-ops (one trivial word or punctuation changed); nothing normalises the model's output to the resume's characters (server/generateResume.js:110 normalises U+2010/2011 for another pipeline only).

## Suggested fix
Normalise once (NFKC; U+2010-2015, U+2212 -> '-'; curly quotes -> straight; NBSP -> space) in cleanEdit for both the resume line and `after`, and keep the resume's original characters when the only difference is a lookalike. Make wordDiff and wsKeywords compare normalised, stemmed tokens against the WHOLE resume (not only the line). Drop edits whose only change is one trivial word or punctuation (low-value filter). Highlight from the normalised diff.

# BUG-013: Download dialog does not trap focus: Tab leaves the modal
Severity: S4
Priority: P2
Status: Open
Flow / TC-ID: Templates & export / accessibility / TC-REG-024 (the title of TC-TPL-009 also promises a trap)
Devices: laptop-chrome, laptop-safari, laptop-firefox
URL: /app/editor, Download PDF dialog
Frequency: Always (7 of 12 Tab presses landed outside the dialog on laptop-chrome)
Build / env: local scratch copy of the working tree on top of c53d3dc, http://127.0.0.1:5273 (fake Supabase, API mocked, no live keys), 2026-11-24 IST
Not a regression: the dialog never trapped focus. Found while checking the BUG-008 fix.

## Steps to reproduce
1. Open Download PDF. Press Tab 12 times.
## Expected
Focus cycles inside the dialog (it is role=dialog aria-modal=true).
## Actual
Focus moves to controls on the page behind the scrim.
## Evidence
- Test: qa/tests/regress.spec.ts TC-REG-024
## Probable cause
src/DownloadPaywall.jsx has focus-in and Escape but no Tab handling or inert background.
## Suggested fix
Trap Tab inside the dialog, or set inert on the app root while it is open.

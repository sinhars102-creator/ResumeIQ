# BUG-004: Title and seniority inflation ('Product Manager' -> 'Senior Product Manager') is only discouraged in the prompt, not blocked in code
Severity: S3
Priority: P0
Status: Verified-Fixed
Flow / TC-ID: Tailoring / claim check / TC-CLAIM-009
Devices: server logic (laptop-chrome run)
URL: POST /api/tailor/*
Frequency: Always for the code path. NOT verified with the real model (no LLM key in the test setup)
Build / env: local scratch copy of branch resume-llm, commit c53d3dc, http://127.0.0.1:5273 (fake Supabase, API mocked, no live keys), 2026-11-24 IST

## Steps to reproduce
1. cleanEdit({target:'T', op:'replace', after:'Senior Product Manager'}, resume, claimContext(resume, jd, '')).

## Expected
A seniority word the resume does not already use for that role is blocked or asked about (the prompt rule says 'Never change job titles or seniority').
## Actual
The edit is returned as a normal suggestion. The only guard is the model following RULES in the prompt; the server checks numbers and skills only.
## Evidence
- Test: qa/tests/claims.spec.ts TC-CLAIM-009

## Probable cause
server/tailorChat.js cleanEdit(): target 'T' goes through unsupportedClaims(), which only looks at skill-type job words; Senior/Lead/Head/Principal/Director are in no list.
## Suggested fix
Block Senior/Lead/Head/Principal/Director/VP/Manager words in target T (and in role lines) unless already present on the resume or said in chat. Test it against the real model before launch.

# BUG-018: No-op filter treats any two non-Latin lines as equal: genuine Hindi/Unicode rewrites are silently dropped
Severity: S3
Priority: P1
Status: Open
Flow / TC-ID: Tailoring / claim filter / TC-AIQ-R03
Devices: server logic, device independent (run on laptop-chrome)
URL: server/tailorChat.js cleanEdit
Frequency: Always (unit-level)
Build / env: local isolated copy of the CURRENT working tree (branch resume-llm, uncommitted on c53d3dc), vite http://127.0.0.1:5612 + real API server http://127.0.0.1:5611 (only an LLM key in env), 2026-11-25 IST

## Steps to reproduce
1. Resume bullet in Devanagari, e.g. U+0909 U+0924 U+094D U+092A ... (Hindi).
2. cleanEdit({target:'E0B0', op:'replace', after:'<a different Hindi line>'}, resume, ctx).

## Expected
A different line is kept as a suggestion.

## Actual
Returns null: plain() = lowercase + replace /[^a-z0-9]+/ with space, so both Hindi strings become '' and compare equal. Any mixed line whose only changes are non-ASCII words is also treated as a no-op. Hinglish/Hindi resumes cannot receive rewrites.

## Evidence
- Test: qa/tests/ai-regress.spec.ts TC-AIQ-R03 (fails)
- Run: qa/runs/2026-11-25_1425/pw-regress2 (trace) and `node qa/llm/esc001.mjs` last lines (plain(Hindi A)===plain(Hindi B): true)

## Probable cause
server/tailorChat.js:247 `plain`: replaces everything that is not a-z0-9.

## Suggested fix
Use a Unicode-aware normaliser (\p{L}\p{N}) after NFKC, as qa/llm/lib.mjs norm() does.

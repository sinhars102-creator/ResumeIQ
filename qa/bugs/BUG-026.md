Build / env: local isolated copy of the CURRENT working tree (branch resume-llm, uncommitted on c53d3dc), vite http://127.0.0.1:5612 + real API server http://127.0.0.1:5611 (only an LLM key in env), 2026-11-25 IST

## Steps to reproduce
1. Upload test-data/sample-resumes/09_Fatima_Sheikh_Talent_Acquisition.docx (the picker's accept filter excludes it; reached with setInputFiles / 'All files').

## Expected
A clear 'Word files are not supported, save as PDF' message.

## Actual
The ZIP bytes ('PK...') were sent to the model as the resume text (7.7 KB); it returned an empty skeleton and the chat shows 'Got it' with name 'Unknown'; a later job paste is answered 'No resume came through'.

## Evidence
- Corpus: qa/runs/2026-11-25_1425/llm-corpus/_docx-misparse/http-026-P1-parse-09-fatima.json (request tail shows PK zip bytes; response is the empty skeleton)

## Probable cause
src/ResumeIQ.jsx:1921-1949 readResumeFileText only special-cases PDF, everything else uses readAsText; src/ResumeLLM.jsx:1251 accept='.pdf,.txt' (no docx, no message).

## Suggested fix
Reject non-pdf/txt types with a message, or add a docx reader (mammoth); do not call the model on binary text.

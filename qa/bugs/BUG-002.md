# BUG-002: Skills evidence check is bypassed for short skill names (Go, R, C#, AI, ML, K8s): they are added to Skills with no evidence
Severity: S2
Priority: P0
Status: Verified-Fixed
Flow / TC-ID: Tailoring / claim check / TC-CLAIM-016, TC-CLAIM-015, TC-CLAIM-017
Devices: server logic, device independent (run on laptop-chrome)
URL: POST /api/tailor/suggest and /api/tailor/chat
Frequency: Always (6 of 8 names tried; Rust and Kafka are correctly blocked)
Build / env: local scratch copy of branch resume-llm, commit c53d3dc, http://127.0.0.1:5273 (fake Supabase, API mocked, no live keys), 2026-11-24 IST

## Steps to reproduce
1. Call cleanEdit({target:'K', op:'add_skills', skills:['Go']}, resume, claimContext(resume, 'Need Go experience', '')) with a resume that has Skills ['SQL'] and no mention of Go.
2. Repeat with R, C#, AI, ML, K8s, Rust, Kafka.

## Expected
Every skill without evidence on the resume or in the chat comes back as { unsupported: [...] } and the user is asked about it.
## Actual
Go, R, C#, AI, ML and K8s are returned as accepted skills to add. A bullet rewrite that adds 'C# and Go' because the job asks for them is also accepted (TC-CLAIM-017, TC-CLAIM-015 for K8s).
## Evidence
- Test: qa/tests/claims2.spec.ts, qa/tests/claims.spec.ts
- Run output: qa/runs/results-full.json (TC-CLAIM-015/016/017 failed)

## Probable cause
server/tailorChat.js: stems() keeps only stems with length >= 3, so 'go', 'r', 'c#', 'ai', 'ml', 'k8' vanish. In cleanEdit add_skills, `[...stems(s)].every(...)` is true for an empty set, so the skill counts as 'shown'. In unsupportedClaims the same stems drop the word before skillLike() sees it.
## Suggested fix
Compare skills as whole normalised strings (lowercase, trimmed) against the resume corpus, not through stems(); treat an empty stem set as unsupported. Allow 1-2 character tokens in the claim check when they are in SKILL_WORDS or contain a digit/symbol. Add tests for Go, R, C#, AI, ML, K8s.


## Regression result (2026-11-24 (regression, working tree on top of c53d3dc, http://127.0.0.1:5273, fake Supabase, API mocked))
Status: Verified-Fixed
TC-CLAIM-016 (Go, R, C#, AI, ML, K8s, Rust, Kafka), TC-CLAIM-017 and TC-CLAIM-015 pass. Probes: 'go-to-market' and 'R&D' are not claims; Go/R/C#/AI/ML are accepted when the resume or the user's chat shows them. Over-blocking side effects are logged in BUG-014.

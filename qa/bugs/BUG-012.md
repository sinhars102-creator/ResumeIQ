# BUG-012: Escape closes the download dialog while a payment is in progress; the payment still completes with no visible dialog
Severity: S4
Priority: P1
Status: Verified-Fixed
Flow / TC-ID: Payments / download dialog / TC-REG-025
Devices: laptop-chrome, laptop-safari, laptop-firefox (keyboard only; phones not applicable)
URL: /app/editor, Download PDF -> Pay step
Frequency: Always
Build / env: local scratch copy of the working tree on top of c53d3dc, http://127.0.0.1:5273 (fake Supabase, API mocked, no live keys), 2026-11-24 IST

## Steps to reproduce
1. Signed in, no downloads left; Download PDF -> Continue -> 'Pay Rs 49 and continue'. (Razorpay was a local fake script: no network, no real payment.)
2. While checkout is open, press Escape on the page.

## Expected
Escape does nothing while a payment step is active (or asks first), so the dialog is still there to show the result.
## Actual
The dialog unmounts. When the fake checkout then calls its success handler, /api/downloads/purchase is still called (verifyCalledAfterClose=true) but the user has no dialog, no 'ready' state and no message. The plan is granted silently; a user who thinks it was cancelled may pay again. Clicking the scrim (onClick onClose) had the same problem before; Escape adds a second route.
## Evidence
- Test: qa/tests/regress.spec.ts TC-REG-025 (annotation escape-during-payment: dialogClosed=true verifyCalledAfterClose=true)
## Probable cause
src/DownloadPaywall.jsx keydown handler calls onClose unconditionally; pay() keeps running after unmount.
## Suggested fix
Ignore Escape (and scrim click) while busy is true. Real Razorpay renders in its own iframe, so a real-device and test-mode check is still needed.

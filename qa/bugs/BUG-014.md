# BUG-014: New seniority and short-skill checks over-block legitimate edits
Severity: S4
Priority: P2
Status: Partially-Fixed
Flow / TC-ID: Tailoring / claim check (found by probe scripts, no spec yet)
Devices: server logic, device independent
URL: server/tailorChat.js cleanEdit, unsupportedClaims
Frequency: Always
Build / env: local scratch copy of the working tree on top of c53d3dc, http://127.0.0.1:5273 (fake Supabase, API mocked, no live keys), 2026-11-24 IST
Safe failure (nothing invented gets through) but real users lose good suggestions.

## Cases wrongly blocked (probe results)
- Title 'Product Manager, Lead Generation' -> blocked as 'lead' (a noun, not a level).
- Summary 'PM who can lead cross-functional teams' -> blocked ('lead' as a verb).
- Summary 'PM building staff scheduling tools' -> blocked ('staff').
- Title 'Product Owner' -> 'Product Manager' blocked: 'manager' is in the SENIORITY list but is a role name, not a level.
- Resume bullet 'Leads sprint planning' does not support title 'Lead Product Manager' (exact word match, no inflections).
- JD mode: a bullet starting 'Go beyond ...' is blocked as a Go claim when the JD says 'Go'; lowercase 'ml' (millilitres) counts as ML when the JD asks for ML.
## Correctly allowed
'Product Manager, Growth', 'Technical Product Manager', 'Product Manager - Leadership', 'Headless CMS', go-to-market, R&D, evidence-backed Go/R/C#/AI/ML adds.
## Suggested fix
Check seniority only at the start of a title, drop 'manager' from the list or compare against the resume's own role words, match inflections (lead/leads/led), and limit the summary check to 'Senior/Lead/Head of' patterns.

# BUG-024: Internal line ids ([K], [E0B6], [E3B2], [Z]) appear in the assistant's replies shown to users
Severity: S4
Priority: P2
Status: Open
Flow / TC-ID: Tailoring / chat replies / TC-AIQ-003, TC-AIQ-010..021
Devices: all devices
URL: /app/editor workspace
Frequency: Always (most replies)
Build / env: local isolated copy of the CURRENT working tree (branch resume-llm, uncommitted on c53d3dc), vite http://127.0.0.1:5612 + real API server http://127.0.0.1:5611 (only an LLM key in env), 2026-11-25 IST

## Steps to reproduce
1. Ask for any change that mentions skills or bullets.

## Expected
Plain wording ('your Skills line', 'the vendor bullet').

## Actual
Replies read 'I cut your [K] list from 15 to 8', 'bullets [E0B6], [E0B7], [E1B5], [E2B4] and [E3B2]', 'certifications line [Z]'.

## Evidence
- Screenshots: qa/runs/2026-11-25_1425/screens/iphone-14/S4-ask-panel-thread.png, qa/runs/2026-11-25_1425/screens/laptop-chrome/C2-projects.png

## Probable cause
server/tailorChat.js:295 RULES ('Refer to resume lines only by their ids in square brackets') is applied to the reply too.

## Suggested fix
Tell the model ids are for edits only, or strip /\[(?:[CTSKZ]|E\d+(?:B\d+)?)\]/ from replies and map them to names.

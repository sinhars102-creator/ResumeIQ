# BUG-001: Hindi/Devanagari resume text is silently dropped from the PDF, and the content check still says everything is in the PDF
Severity: S2
Priority: P0
Status: Verified-Fixed
Flow / TC-ID: Templates & export / TC-TPL-006
Devices: all 7 projects (laptop-chrome/safari/firefox, iphone-14/se, pixel-7, budget-android)
URL: /app/editor -> Download PDF
Frequency: Always (7/7)
Build / env: local scratch copy of branch resume-llm, commit c53d3dc, http://127.0.0.1:5273 (fake Supabase, API mocked, no live keys), 2026-11-24 IST

## Steps to reproduce
1. Open a chat whose resume has Hindi text (name 'आशा राव', role 'प्रोडक्ट मैनेजर', company 'अक्मे', Hindi summary and bullet).
2. Tap Download PDF; the template step shows the green line 'Everything on your resume is in this PDF (N items checked)'.
3. Continue and download the PDF; open it.

## Expected
Either the Hindi text is in the PDF, or the check warns that it cannot be drawn and names what is missing.
## Actual
On screen the Hindi shows correctly. In the downloaded PDF the name, role, company, summary and bullet are all gone (name line is empty). The check showed a tick and the dialog said 'Your PDF has been saved'. Text read back from the PDF: 'Product Manager asha@example.com · Bengaluru SUMMARY 5 · INR 12 EXPERIENCE · 2019-2023 • MAU 40% ...'. A candidate would send out a resume with no name.
## Evidence
- Screenshot: qa/runs/full/templates-Templates-previe-75d8c-if-the-PDF-cannot-draw-them-laptop-chrome/test-failed-1.png
- PDF: qa/runs/full/templates-Templates-previe-75d8c-if-the-PDF-cannot-draw-them-laptop-chrome/hindi.pdf
- Trace: same folder, trace.zip

## Probable cause
src/resumePdf.js:81-94 pdfSafeText() removes every character the standard PDF fonts cannot draw. src/preservation.js:15 squash() runs the same pdfSafeText on BOTH the expected text and the PDF text, so a Hindi needle shrinks to an empty string and `needle && !haystack.includes(needle)` skips it. The check can never fail for non-Latin text.
## Suggested fix
(1) Embed a Unicode font (e.g. Noto Sans + Noto Sans Devanagari) in jsPDF when the resume has non-Latin characters. (2) Independently, make checkPreserved compare the raw expected text: if pdfSafeText(text) loses characters, count the entry as missing and show the warning. Add a unit test with a Hindi name.


## Regression result (2026-11-24 (regression, working tree on top of c53d3dc, http://127.0.0.1:5273, fake Supabase, API mocked))
Status: Verified-Fixed
TC-TPL-006 passes on all 7 projects (was failing on 7). Content check now warns and names the Hindi items instead of the green tick. Unit probe: Cyrillic, Greek, CJK, Hindi and a stray 'Ł' are reported missing; accented Latin (José, Müller, Straße, Ångström), ligatures and ₹ are not (no false warning). Known limit, not a regression: Hindi is still not drawn in the PDF, and the user can still press Continue and download a PDF with an empty name line after reading the warning.

# BUG-023: Assistant message does not match what the list shows: wrong counts, wrong verb, claims of done work for pending cards
Severity: S3
Priority: P1
Status: Open
Flow / TC-ID: Tailoring / chat replies / TC-AIQ-007, TC-AIQ-010, TC-AIQ-002
Devices: laptop-chrome (content)
URL: /app/editor workspace
Frequency: Intermittent per model output; 3 of 12 scripted turns on Opus
Build / env: local isolated copy of the CURRENT working tree (branch resume-llm, uncommitted on c53d3dc), vite http://127.0.0.1:5612 + real API server http://127.0.0.1:5611 (only an LLM key in env), 2026-11-25 IST

## Steps to reproduce
1. 'can you make it fit one page?'  2. 'reduce skills to the top 10'  3. 'reduce core competencies...'

## Expected
Counts and verbs in the reply match the cards; claims about page count are checked.

## Actual
'I dropped 9 low-impact bullets' with 8 remove cards. 'reduce skills to the top 10' -> 'I expanded your [K] list to 10 by keeping the earlier 8 and adding back Mixpanel and Amplitude' (the card goes 24 -> 10; the model was reasoning from an earlier, reset suggestion). 'I trimmed...', 'I dropped...' are said while every card is still pending and the resume on screen is unchanged. 'this should fit one page in most templates' is asserted with no page count measured (the chat call never receives the page count that the review pipeline uses).

## Evidence
- Data: qa/runs/2026-11-25_1425/scenarios/turns.json B1-onepage, B4-skills-top10, A1
- Screenshot: qa/runs/2026-11-25_1425/screens/laptop-chrome/B1-onepage.png

## Probable cause
server/tailorChat.js:556 reply is the model's free text; no reconciliation with `edits.length`, targets or ops; src/ResumeLLM.jsx act.ask appends only the card count.

## Suggested fix
Generate the count/verb part of the reply from the cards in code, keep the model text for explanation only, and pass `pages` to chatTurn for page-fit claims.

# BUG-009: Malformed or oversized JSON to the API returns an HTML stack-trace page with server file paths
Severity: S4
Priority: P2
Status: Verified-Fixed
Flow / TC-ID: API / TC-API-004
Devices: server, device independent
URL: POST /api/tailor/chat
Frequency: Always on a local run. Production behaviour depends on NODE_ENV (not set in render.yaml or vercel.json; verify)
Build / env: local scratch copy of branch resume-llm, commit c53d3dc, http://127.0.0.1:5273 (fake Supabase, API mocked, no live keys), 2026-11-24 IST

## Steps to reproduce
1. curl -X POST /api/tailor/chat -H 'content-type: application/json' -d '{bad'.
2. Send a 5 MB body.

## Expected
A JSON error such as {error:'Invalid request'} with 400 or 413.
## Actual
An HTML page with the stack trace and absolute file paths (/Users/.../node_modules/...). The chat shows 'Request failed (400)' because the client cannot parse it.
## Evidence
- qa/runs/evidence/api-malformed-json.txt

## Probable cause
server/index.js has no error-handling middleware after express.json().
## Suggested fix
Add app.use((err, req, res, next) => res.status(err.status || 500).json({ error: ... })) and set NODE_ENV=production on the host.
